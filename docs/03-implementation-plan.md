# REDHOOD · 구현 계획

문서 버전 v0.1 (2026-08-05) · 대응 문서: 01-concept.md, 02-data-structure.md

## 1. 기술 방침

| 항목 | 결정 | 이유 |
|---|---|---|
| 스택 | 순수 HTML + CSS + 바닐라 JS (빌드 도구 없음) | GitHub Pages에 그대로 배포. 프레임워크 학습 비용 제거, 수정 → 푸시 → 반영이 최단 경로 |
| 렌더링 | DOM 기반 (Canvas 미사용) | 카드 UI는 DOM이 유리 (터치, 텍스트, 접근성). 연출은 CSS 트랜지션 |
| 데이터 | `data/*.json`을 fetch로 로드 | 02 문서 스키마 준수. 엔진과 데이터 완전 분리 |
| 저장 | localStorage (런 이어하기 + 통계) | 노드 진입 시점마다 자동 저장 |
| 화면 | 세로 고정, 기준 뷰포트 390×844 | 가로 회전 시 "세로로 돌려주세요" 오버레이 |
| 배포 | GitHub Pages (main 브랜치 루트) | 푸시 즉시 배포 |
| PWA | manifest.json + service worker | 홈 화면 설치, 전체화면 실행, 오프라인 플레이 |

## 2. 파일 구조 (목표)

```
redhood/
├── index.html            # 단일 진입점
├── manifest.json         # PWA 매니페스트
├── sw.js                 # 서비스 워커 (오프라인 캐시)
├── css/style.css
├── js/
│   ├── main.js           # 부트스트랩, 화면 전환
│   ├── data.js           # JSON 로더 + 검증
│   ├── battle.js         # 전투 상태 머신
│   ├── effects.js        # 효과 DSL 인터프리터
│   ├── resource.js       # 무기 자원/열광 처리
│   ├── map.js            # 맵 생성·이동
│   ├── run.js            # 런 상태 (덱, HP, 진행도, 세이브)
│   └── ui/               # 화면별 렌더러 (battle, map, reward, rest)
├── data/                 # 02 문서의 JSON 6종
├── assets/               # 아이콘, (추후) 일러스트
└── docs/                 # 설계 문서
```

## 3. 마일스톤

각 마일스톤은 "플레이 가능한 상태"로 끝나는 것을 원칙으로 한다.
완료 기준(DoD)을 통과하면 main에 푸시 → Pages에서 성권님이 직접 체감 테스트.

### M1 — 전투 코어 (총 1무기, 하드코딩 1전투)

턴 루프: 드로우 5 → 카드 사용 → 턴 종료 → 적 행동. 탄환 코스트, 방어도,
적 의도 표시, 승리/패배 판정까지. 데이터는 이 단계만 js에 임시 하드코딩.

**DoD**: 모바일 브라우저에서 가시덤불 1마리를 총으로 잡을 수 있다.

### M2 — 데이터 주도화 + 3무기

JSON 로더, 효과 DSL 인터프리터, 상태효과 5종, 랜턴(기름 이월)·낫(열광 게이지+단계 패널티) 구현.
중립 카드 코스트 환산 규칙 포함. M1의 하드코딩 제거.

**DoD**: weapons.json에서 무기를 골라 같은 전투를 3무기 모두 다른 감각으로 플레이할 수 있다.
카드 수치를 JSON에서 바꾸면 코드 수정 없이 반영된다.

### M3 — 런 루프 (1막 미니 완성)

맵 생성·노드 이동, 전투 보상(카드 3택1), 휴식, 엘리트, 늑대 보스(2페이즈),
사망/클리어 화면, localStorage 이어하기.

**DoD**: 시작부터 늑대까지 한 런을 완주(또는 사망)할 수 있다. 앱을 껐다 켜도 런이 이어진다.

### M4 — 모바일 UX 패스

카드 터치 드래그(또는 탭-탭 방식 비교 후 선택), 피해·자원 연출, 열광 게이지 시각화,
세이프 에어리어(노치) 대응, 가로 회전 가드.

**DoD**: 성권님 폰에서 "조작 때문에 죽는" 일이 없다.

### M5 — PWA + 배포 마감

manifest(아이콘, 세로 고정, standalone), 서비스 워커 캐시(버전 태그로 갱신 관리),
설치 유도 UI("홈 화면에 추가" 안내), GitHub Pages 최종 점검.

**DoD**: 홈 화면에서 아이콘으로 실행, 주소창 없는 전체화면, 비행기 모드에서도 플레이 가능.

### M6+ (프로토 이후, 범위 외)

카드 강화, 유물, 상점·이벤트 노드, 2~3막, 슬더스 골자에서의 본격 변주, 사운드.

## 4. 협업 방식

| 역할 | 담당 |
|---|---|
| 규칙 설계, 밸런싱, 카드/적 테이블 수치 | 성권님 (JSON 직접 수정 또는 텍스트로 전달) |
| 엔진·UI 구현, 데이터 반영, 배포 | Claude |
| 문서 | 공동 — 규칙 변경은 반드시 docs 갱신 후 구현 |

브랜치는 프로토 동안 main 단일 운용 (혼자+AI 협업이라 PR 오버헤드 불필요).
커밋 단위는 마일스톤 내 기능 단위. 각 마일스톤 완료 시 태그 (`m1`, `m2`, …).

## 5. 리스크 메모

| 리스크 | 대응 |
|---|---|
| 낫 밸런스 (무비용 구조라 붕괴 위험 최대) | M2에서 가장 먼저 실기 테스트. 열광 수치는 frenzy.json에서 즉시 조정 가능하게 |
| iOS 사파리 PWA 제약 (저장소 정리, 알림 등) | 오프라인 캐시·localStorage 중심의 보수적 설계. 푸시 알림 등은 사용 안 함 |
| 효과 DSL 확장 남발 | op 추가는 "카드가 요구할 때만" 원칙 (02 문서 §2.3) |
| 세이브 호환 | 카드 id 불변 원칙 + 세이브에 스키마 버전 기록, 불일치 시 런 폐기 |
